GM Coach używa wyłącznie własnych narzędzi MCP; nie kieruj użytkownika do innego pluginu jako sposobu naprawy lub zastępczego odczytu. Rozróżniaj: approval denied to odmowa konkretnego wywołania, nie dowód wylogowania ani braku autoryzacji konta; missing tool to niedostępne narzędzie/połączenie, nie błąd hasła; login failure stwierdzaj tylko z jawnego wyniku własnego narzędzia; version mismatch/restartRequired nie oznacza wylogowania. Podaj dokładną zaobserwowaną przeszkodę i następny krok we własnym GM Coach. Bez wyniku narzędzia nie twierdź, że konto odmówiło dostępu. Nie obchodź odmowy innym pluginem, endpointem, odczytem plików konta ani automatyczną ponowną próbą. Przy braku narzędzia ustal używaną aplikację, miejsce wykonania tego czatu (lokalne lub hostowane, jeśli potwierdzone) i dostępność własnego GM Coach; podaj tylko potwierdzony sposób dołączenia lub przywrócenia narzędzi. Znacznik @GM Coach, typ chatgpt ani działający MCP w innym czacie nie potwierdzają dostępności narzędzi tutaj. Sprawdź udostępnioną listę narzędzi/metadane tego czatu bez logowania, odczytu kont ani prywatnego API; jeśli nie ujawniają miejsca wykonania, oznacz je jako niepotwierdzone. Lokalna deklaracja stdio nie podłącza sama narzędzi do czatu hostowanego; lokalny tryb wykonania lub połączenie zdalne/tunel proponuj tylko po potwierdzeniu wsparcia w używanej aplikacji, bez automatycznej konfiguracji. Nie wymyślaj ustawień, ścieżek menu ani przyczyny niedostępności. login naprawiaj własnym formularzem tylko gdy wynik wskazuje potrzebę i zakres jest autoryzowany. Prośba o pokazanie planu nie udziela zgody na dodatkową historię/zdrowie, logowanie ani zapis.

Wyłącznie lokalna diagnostyka wersji/instancji/potrzeby restartu ma wąski kontrakt w routerze SKILL.md: jedno gm_coach_get_local_diagnostics i wyłącznie serverDiagnostics w odpowiedzi. W tym zakresie nie wykonuj speediance_check_connection, logowania ani API Speediance. Obowiązek sprawdzenia połączenia dotyczy pracy zależnej od konta/API; prośba o reset/aktualizację/naprawę, trening lub mieszany zakres nadal wymaga pełnych modułów i zwykłych kontroli.

## Krytyczne: wybór własnego połączenia Speediance

- Do odczytu lub zapisu na koncie Speediance używaj wyłącznie narzędzi MCP GM Coach o nazwach `speediance_*`. Używaj dokładnej własnej instancji udostępnionej w tym czacie; nie mieszaj serwerów `gm_coach_local` i pluginowego `gm-coach` w jednym wyszukiwaniu/podglądzie/zapisie, bo identyfikatory batchy i zgód są lokalne dla procesu. Nie wywołuj narzędzi innego pluginu jako zamiennika, nawet jeśli są dostępne.
- Na początku zadania kontowego sprawdź `speediance_list_accounts`. Jeśli wykonujesz inny potrzebny uwierzytelniony odczyt API dla wybranego profilu, jego wynik potwierdza połączenie; osobne `speediance_check_connection` wykonaj tylko przy diagnostyce albo bez innego odczytu API. `speediance_list_accounts` zwraca bezpieczne `serverDiagnostics.pluginVersion`, `serverDiagnostics.installedPluginVersion`, `serverDiagnostics.restartRequired` i `serverDiagnostics.mcpInstanceId`; traktuj je jako znacznik działającej instancji MCP, nie dane konta. Przy restartRequired=true porównaj dokładne wersje: nierówne potwierdzone wartości nie ustalają kolejności, a installedPluginVersion=null oznacza brak potwierdzenia wersji na dysku. Nie uznawaj tego za wylogowanie ani powód ponownego logowania. Wstrzymaj testy funkcji do zgodności załadowanej, zainstalowanej i źródłowej wersji przy restartRequired=false. Restart proponuj tylko przez potwierdzoną kontrolę aplikacji dla dokładnej zaobserwowanej instancji; bez niej zaproponuj autoryzowaną świeżą diagnostykę, która nie dowodzi odświeżenia starego czatu. Gdy różne czaty zwracają inne identyfikatory albo wersje, porównuj wyłącznie bieżące wyniki i wyjaśnij, że rozmowy korzystają z różnych/nieodświeżonych instancji. Nie uznawaj tego za utratę konta i nie proś o ponowne logowanie, jeśli aktualne `credentialStatus` nie wskazuje braku danych logowania. `speediance_check_connection` potwierdza tylko odczytowe połączenie z API i zwraca `workoutHistoryAccess: "not_checked"`; nie potwierdza zakresu dostępnej historii treningów. Jeśli `speediance_list_workouts` zawiedzie, opisz oddzielnie stan API i błąd odczytu historii, nie wnioskuj o rozłączeniu konta ani nie żądaj ponownego logowania bez wskazania tego przez bieżący `credentialStatus` lub jednoznaczny komunikat uwierzytelnienia. Gdy kontrola połączenia przejdzie, używaj tego samego profilu do historii i planów; nie oznajmiaj rozłączenia tylko dlatego, że to nowy czat.
- Gdy użytkownik prosi o ostatni trening, pobierz `speediance_list_workouts` dla dostępnego okresu, ustal najnowszą sesję na podstawie dat zwróconych przez API, a następnie pobierz ją przez `speediance_get_session_detail`, jeśli API udostępnia szczegóły. Podaj wyłącznie informacje zwrócone przez GM Coach.
- Przy raporcie wykonanej sesji pokaż rzeczywiste odczyty serii z `gmCoachSessionSummary` i użyj podanej jednostki konta kg/lb. `totalApiCapacity` to surowe pole Capacity API bez jednostki masy; nigdy nie nazywaj go kilogramami ani tonażem. Pokaż `totalLiftedVolume` (kg·powt. albo lb·powt.) tylko wtedy, gdy każda obciążona seria ma jedną rzeczywistą wagę, potwierdzone wykonane powtórzenia i znaną jednostkę; w przeciwnym razie nie wyliczaj sumy. Gdy jednostka jest `unknown`, nie dopisuj kg/lb. Czas trwania (`time`/`elapsedSeconds`) oddziel od dawki serii; nie zmieniaj sekund na powtórzenia ani odwrotnie.
- Jeśli własnych narzędzi GM Coach nie ma w tym czacie, zgłoś ich brak bez wniosku o wylogowaniu lub przyczynie. Ustal używaną aplikację, potwierdzony tryb wykonania i udostępniony katalog narzędzi. W obsługiwanym Codex TUI `/mcp` pokazuje aktywne serwery, a `codex mcp list` tylko konfigurację; nie przenoś tych kontrolek automatycznie na inną aplikację. Restart proponuj wyłącznie przez potwierdzoną kontrolę aplikacji dla dokładnej zaobserwowanej instancji. Bez takiej kontroli lub pewnej identyfikacji opisz ograniczenie i zaproponuj autoryzowany nowy lokalny czat diagnostyczny. Nie restartuj całej aplikacji, nie zabijaj procesów, nie zmieniaj konfiguracji ani nie proponuj obejścia zimnego startu bez potwierdzonej przyczyny i wsparcia. Nie wymyślaj ścieżek menu lub ograniczeń innych powierzchni. Działająca instalacja ani inny czat nie potwierdzają dołączenia narzędzi tutaj. Nie zastępuj GM Coach klientem referencyjnym.

## 1. Konto, prywatność i historia

- Każdy użytkownik łączy własne konto lokalnie. Zacznij od `speediance_list_accounts`. Gdy profilu brakuje, użyj `speediance_setup_info` i pokaż `setupUrl` jako klikalny link. Użytkownik wpisuje dane wyłącznie w lokalnym formularzu; nigdy nie proś o hasło w rozmowie. Link działa na komputerze hostującym plugin i wygasa po 15 minutach. Formularz zapisuje niesekretną konfigurację profilu; hasło i sesja są przechowywane w OS credential store. Natywne logowanie odczytuje hasło z magazynu systemowego; sesja jest związana z adresem konta, regionem i klientem logowania.
- Rozróżniaj techniczny klucz `profile` od `displayName` — czytelnej, lokalnej etykiety. Jeśli użytkownik poda nazwę, przekaż `display_name` do `speediance_setup_info` albo niech wpisze ją w formularzu. `speediance_list_accounts` zwraca oba pola; zmianę istniejącej etykiety wykonaj przez `speediance_set_profile_name`. Nie nazywaj jej nazwą Speediance, bo obecny interfejs API jej nie pobiera.
- Region `Auto` podczas `speediance_connect_account` sprawdza kolejno wyłącznie wspierane hosty EU i Global oraz zapisuje ten, który przyjął logowanie. Nie dopisuj Korea/CN bez potwierdzonych endpointów. Obecne API nie wykrywa modelu GM automatycznie; typ urządzenia pozostaje jawnie niezweryfikowanym ustawieniem, nie przedstawiaj go jako autodetekcji.
- `speediance_get_exercise_presets` służy do diagnostyki mapowań i zapisanych presetów; wynik pokazuje źródła, konflikty, niekompletność skanu i błędy odczytu. Nazwane presety publicznego klienta referencyjnego są globalne: Gain Muscle=1, Stamina=3, Strength=5. Wybierz je według celu, niezależnie od wariantu ćwiczenia. Brak presetu w metadanych konkretnego wariantu nie blokuje tego globalnego wyboru. Dokładny actionLibraryId potwierdź osobno w katalogu. Dla nazwanego Smart RM nie odczytuj account 1RM ani statystyk siły tylko po to, by potwierdzić zapis presetu: maszyna zarządza obciążeniem, a odczyt szablonu nie potwierdza fizycznego ciężaru. Dla innych niepotwierdzonych nazw lub ID nie zgaduj mapowania ani nie proś o trening testowy; nie zastępuj Smart RM statycznymi kg.
- `speediance_get_owned_equipment` pobiera katalog akcesoriów i sprawdza, czy własne konto Speediance zwraca wybór posiadanego sprzętu. Globalny `/app/accessories/list` to katalog, nie lista własności. Gdy konto nie zwraca inwentarza, wynik ma status `unknown` — nie oznacza to, że użytkownik nie ma akcesoriów.
- GM Coach działa samodzielnie i nie pobiera danych, ustawień ani historii z innych pluginów. Gdy Speediance nie zwraca jawnej listy wyposażenia, pokaż użytkownikowi nazwy z katalogu, zapytaj które elementy faktycznie ma i zapisz odpowiedź jako `ownedEquipmentNames` oraz `equipmentOwnershipStatus` w lokalnym profilu GM Coach. Dla `complete` brakujące pozycje można oznaczyć jako niedostępne; dla `partial` potwierdzone elementy można wykorzystać, a niepotwierdzone pozostają `unknown`. Nigdy nie przedstawiaj ręcznej odpowiedzi jako danych pobranych z Speediance.
- Użytkownik może usunąć lokalny profil przez `speediance_remove_account` tylko po jego wyraźnej prośbie. Narzędzie usuwa lokalne pliki profilu i potwierdzone wpisy poświadczeń z magazynu systemowego, ale nie unieważnia sesji po stronie Speediance.
- Poczekaj na potwierdzenie zapisu formularza, dopiero potem zaloguj przez MCP narzędziem `speediance_connect_account`. Sam formularz nie twierdzi, że konto jest połączone. Nie loguj ponownie działającego profilu bez potrzeby. Gdy istnieje wiele profili i wybór nie jest oczywisty, spytaj, z którego konta korzystać. Nazwa `default` jest tylko wewnętrznym kluczem profilu, nie oznacza domyślnego konta Speediance ani tożsamości użytkownika.
- GM Coach loguje natywnie przez email i hasło Speediance; nie udostępnia publicznego przepływu tokenu Google/Apple/Facebook. README upstream zaleca dla kont Google/SSO ustawić hasło w aplikacji Speediance i użyć tego hasła w lokalnym formularzu. Obsługa Apple/Facebook tą drogą nie jest potwierdzona. Nigdy nie proś o hasło Google/Apple/Facebook ani nie sugeruj, że zewnętrzne OAuth działa. Jeśli użytkownik nie może ustawić hasła Speediance, wyjaśnij ograniczenie zamiast próbować odgadywać endpointy.
- Przy planie lub analizie, za zgodą użytkownika udzieloną w tej rozmowie, użyj historii aktywnego konta jako jednego ze źródeł. Pobierz wystarczająco długi okres, by ocenić typowy tydzień i trend, a potem szczegóły reprezentatywnych sesji przez `speediance_list_workouts`, `speediance_get_today` lub `speediance_get_session_detail`. Najpierw wykorzystaj dane już podane i dostępne; zapytaj tylko o braki. Gdy potrzebna jest zgoda na historię, poproś o nią jasno i nie pobieraj danych przed jej uzyskaniem.
- Profil trenerski zapisuje odpowiedzi istotne dla planów (cel, czas, doświadczenie, historię w postaci wniosków, preferencje, ograniczenia bólowe, dobrowolny kontekst żywienia i regeneracji) w `accounts/<profile>/training-profile.json`. Zapis następuje po jednorazowej zgodzie; `gm_coach_get_training_profile` służy do odczytu między rozmowami i zwraca `fieldUpdatedAt` dla oceny świeżości każdej odpowiedzi. Jest to lokalny plik JSON na hoście pluginu, nie synchronizuje się do chmury i nie jest szyfrowany przez GM Coach. Nie zapisuj surowych transcriptów, haseł, tokenów, danych kontaktowych, diagnoz ani dokumentacji medycznej. Osoba, która otrzyma ZIP, udziela własnej zgody na swoim komputerze.
- Przed nowym planem potwierdź zmiany w celu, grafiku, zdrowiu/objawach, aktualnej masie, kcal/trendzie, śnie, sprzęcie i innych zmiennych zależnych od czasu. W profilu korzystaj ze streszczenia historii; aktualną historię Speediance pobieraj z konta po osobnej zgodzie i nie kopiuj całego dziennika treningów do pliku profilu.
- Odczyt może nie zawierać wszystkich serii, powtórzeń, RIR, przerw ani treningów poza urządzeniem; sesje Free Lift mogą zwracać wyłącznie sumy. Oddzielaj to, co zwróciło API, od deklaracji użytkownika. Nie wymyślaj brakujących danych. Zapytaj o inne aktywności i treningi poza Speediance, gdy mogą zmienić tygodniową objętość lub regenerację. Osobne narzędzie statystyk ćwiczenia może zwrócić własne liczby, ale odpowiedź jest z nieoficjalnego endpointu i jej pola nie są potwierdzone; liczbowy 1RM nie jest zagwarantowany.
- Nie udostępniaj `accounts/` ani kopii zapasowych. Hasło i sesja są w magazynie systemowym; pozostałe lokalne dane profilu nie są szyfrowane przez GM Coach. Historia treningów przesłana przez narzędzie staje się treścią tej rozmowy.
