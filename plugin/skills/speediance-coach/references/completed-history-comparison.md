# Exact completed session comparison

Reads only the caller's resolved profile, while holding its mutation lock. The initial fingerprint includes credentials, login client type, region, device type and static protocol configuration. Every history and current-unit GET uses the production beforeSend transport callback and pre/postresponse fingerprint checks. Any detected drift throws; it must not degrade to a successful partial result. Checkpoint checks cannot prove absence of an unobservable A→B→A change between checks.

Selection requires two explicit positive int64 IDs, program/free/course/ai namespace and actual calendar dates. Program/free identity is verified in the dated mobile summary feed. Course/AI identity is verified by the existing completed calendar helper, which revalidates before detail GET. No alternate namespace probing, automatic latest, name matching or calendar reservation substitution. The exact supplied group and variant IDs are filters, not proof of catalog membership; caller must obtain them from the confirmed exercise catalog. The returned raw records must independently confirm both IDs.

Uses actual native reader, completed-exercise scan and workout normalizer. Current userinfo supplies a unit when explicitly reported. Raw userinfo and health fields are discarded. Historic unit stability remains unverified; any load change is conditional on applying the same current account unit to both dates. Missing unit, sportMode, preset, scale/source provenance or side identity prevents the corresponding load comparison. Peak cable telemetry remains a separate metric and is never multiplied by repetitions or converted to 1RM.

Series counts mean returned normalized sets, not necessarily the full training dose or working sets. Side 0/1/2 stays a literal API code; do not translate it to left/right/bilateral without independent evidence. Equal dates do not establish ordering. Repeated occurrences are reported ambiguous instead of merged. Missing results, unsupported older dates or resource bounds are explicit coverage diagnostics.

Resource bounds: exactly two selected sessions; existing scanner's 365-day window; at most 1000 sets per session / 2000 combined; up to 20 seconds scanning each selection / 40 seconds combined checkpoint budget; 64 comparison rows, 200 sets per occurrence, 64 changes and 128 diagnostics. These are resource policies, not physiological thresholds. In-flight network calls follow transport timeout; wall checkpoints are not a hard real-time cancellation guarantee.

Present a readable table of observed results with unit and qualification. Do not claim physiological adaptation, improvement, readiness, RIR, working-set classification, cable tonnage or Epley 1RM. Existing general history tools retain their legacy behavior; this bounded tool alone adds initial fingerprint binding to its entire scan.
