## Load and exercise scope

The active reference client strength/preference tools key assessed and saved anchors by
exercise **groupId**. Its static suggest_load takes groupId. The public reference client
statistics endpoint also takes the group ID; the writer resolves the catalog
variant separately. A group anchor can therefore accompany any independently
confirmed variant in that group. If the record explicitly names a variant,
preserve that narrower scope and reject a different variant. Never apply an
anchor to another group or account.

Smart RM is a named machine preset: Gain Muscle, Stamina or Strength. A historically inspected reference client tool description claimed account 1RM and preset percentages (Gain Muscle 65%, Strength 83%; no Stamina percentage was supplied). This is dated description evidence, not a verified physical firmware formula or a current load oracle. Preserve the named machine preset; do not calculate or report kg/%1RM from those claims. Public UI defaults 13/17/7 are internal RM selector values, not percentages or scientific doses, and are independent of reps and RIR. A screenshot showing kg together with 50%1RM establishes only that displayed label; it does not identify the selected preset or prove its write contract.
Coach requires a fresh consent-gated observation of an explicit reported account
1RM for groupId, with the catalog variant confirmed separately. An explicit
actionLibraryId in the statistic narrows its scope and must match. Local anchors
and estimated e1RM do not replace account presence; kg/lb is not required for
this Smart RM readiness check.

Customize is a distinct static per-set load, with preset -1 and empty RM
counters. The pinned public writers have two separate unit contracts:
[hbui3's legacy Python writer](https://github.com/hbui3/UnofficialSpeedianceWorkoutManager/blob/4e12bc6108f43c2705e935aa3d5db563cb8a3c06/api_client.py)
and the [Go writer](https://github.com/stozo04/speediance-cli/blob/f8157ef94171125c252b02e598e7534838fd407b/internal/template/template.go)
serialize supplied kg to wire pounds using 2.2; the
[Labatt Python writer](https://github.com/labatt/speediance-smartgym-workout-manager/blob/fdd62c8fcecbb22f195ca9d86020026173d6cb78/api_client.py)
serializes supplied weight verbatim in the account's configured unit, to one
decimal. Coach keeps `legacy-reference-client-wire-lb-get-kg` and
`account-unit-verbatim` separate; the latter requires a qualified account-bound
reference through `static-protocol-context.mjs`, not an inferred default switch.
An explicitly authorized `fixed-kg` prescription remains kilograms independently
of the account's display unit; its wire encoding follows the selected qualified
static protocol. A Customize source unit must remain explicit. These are
software interchange contracts, not proof of delivered physical resistance,
firmware calibration or full private reference client load-selection parity. Never derive
Customize or fixed kg from a Smart RM marker or selector. An authorized one-time `get_strength_profile` comparison returned
reference client’s complete **universal** `repMaxCurve` on 2026-10-02. Its 20 explicit
points are now stored in Coach's serializer; these are observed software data,

## Performed exercise sets — 1.0.65

Use `gm_coach_get_exercise_history` with `include_sessions=true` when planning
needs actual historical performed sets, after consent to account-history access.
The scan matches the selected `groupId`; `session_days` is 1–365 (default 90),
and `session_limit` is 1–30 (default 10). Report the scanned scope, `partial`
status, omitted sessions and errors. No match within those bounds does not prove
that the user never performed the exercise. Weekly `dayStr` aggregates remain
separate from actual session dates and sets.

Short Free Lift sessions with an empty standard detail may use a read-only
`freeTrainingDetail` fallback. Cardio is excluded from that resistance-set
fallback. This feature does not establish parity with reference client’s full private
history-based load resolver, nor make an Epley estimate its verified 1:1 algorithm.
