This import mapping does not itself clamp amounts/rests to preset ranges. The editor's input handler separately applies the public [workout-logic.js](https://github.com/hbui3/UnofficialSpeedianceWorkoutManager/blob/main/static/workout-logic.js) rules via `validateAndClamp`. These are mutable main-branch source observations, not firmware or account API evidence.

Coach's local JSON inspection preserves every imported amount and rest without copying that unit inference or defaulting a zero rest to 60. Imported dose units remain unknown, including an unverified supplied seconds field. Unknown presets do not acquire guessed ranges. These warnings neither establish an account API limit nor approve a prescription or authorize clamping.

reference-client-targeted export specifically emits zero rest as JSON string `"0"`: the observed importer evaluates that truthy string as zero, whereas numeric `0` falls back to 60 seconds. Positive rests remain numeric. The prescription and direct Speediance API writer remain unchanged. `representationNormalizations` discloses each affected exercise/set separately from static-load normalization; this is public-source interoperability evidence, not account or firmware verification. Do not silently replace zero rest with 60 or describe the interchange export as lossless/scientifically approved.

The same captured importer uses `parseFloat(String(s.weight ?? 0).replace(',', '.'))`. Coach inspection accepts whole decimal weight tokens such as `11,5`, preserving the original string and disclosing comma spelling interpretation. It deliberately rejects suffix/prefix junk, multiple/mixed separators and exponent forms rather than copying `parseFloat` prefix acceptance. This spelling support does not infer units, change non-weight parsing or authorize loads: static source units stay unknown unless supplied; named integer selectors remain unapproved metadata and fractional selectors remain invalid. Unknown presets remain unknown.

## Confirmed candidate: official-course calendar reservation

Public `schedule_course(date_str, course_id, status)` performs:

```text
POST /api/app/courseReservation
{ status: 1 | 0, deviceType, thatDay: date_str, courseId: course_id }
```

The relative route for Coach's existing API adapter is `/app/courseReservation`; its adapter supplies the `/api` prefix. Status 1 reserves an official course; status 0 removes its reservation. The public method returns the response's `data`, defaulting to false. This report confirms public client behavior only; it contains no live API verification.

A future implementation can extend existing bounded official-course discovery with explicit selected course ID/date/device, separate preview and confirmation, serialized writes, sanitized errors, permission checks without bypass, and calendar readback. Do not confuse official `courseId` reservations with saved-template code reservations. This feature has not been implemented by this audit.
